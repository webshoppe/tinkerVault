# Releases

Self-contained snapshots of each shipped version, exactly as they were packaged at the time (own `index.html`, `manifest.json`, `sw.js`, icons/favicons, `README.md`, `VERSION`, `docs/USER_GUIDE.md`; no external dependencies, each folder runs on its own).

| Folder | Version | Notes |
|--------|---------|-------|
| `v1.0.0/` | 1.0.0 | First shipped release, 2026-07-18. Connection screen, approve/deny of tool calls, run stop, session browse/open/create/fork, installable PWA shell. Run monitoring uses polling, not SSE, due to a CORS gap on the server's events endpoint. |
| `v1.1.0/` | 1.1.0 | 2026-07-18. Adds a per-message toolbar (Copy on any message, Rerun on user messages, resubmits the exact input as a new run) and an in-app version label next to the header title, read from `VERSION` at runtime. Also the first release folder created after the app root's `docs/` + `build-process/` restructuring, matching the rest of the monorepo. |
| `v1.2.0/` | 1.2.0 | 2026-08-07. Adds a footer link row (Source/Docs, always visible regardless of connection state) and client-side session auto-naming, sessions with no server-provided title now derive a display name from the first user message via the server's `preview` field, display-only, no server write. Also closes out an investigation into distinguishing a refusal from a completed action in the UI: the live API exposes no field to tell the two apart, so no UI change shipped for that, a one-time console warning documents the gap instead. Archived as of 1.2.1. |
| `v1.2.1/` | 1.2.1 | 2026-08-12. Fixes two bugs in the approval-card path: `submitApproval()` was sending a request body the server's approval endpoint never actually read (`{decision, approved, approval_id?}` instead of `{choice: ...}`), so every approve/deny had been failing with HTTP 400 since 1.0.0, silently re-showing the same pending card. Also replaces a misleading "(unknown)"/"null" tool-detail display with an honest message for approvals that don't carry a tool name or arguments, mainly shell/terminal commands. Same file as the one at the app root. |

The files at the app root (`index.html`, `manifest.json`, `sw.js`, icons, `README.md`, `VERSION`, `docs/`) always mirror the newest release (right now that's `1.2.1`). Grab the root copy if you just want the current app; use a specific version folder here if you need an older one, or want to compare versions directly. `PROJECT_SUMMARY.md` and `CHANGELOG.md` at the app root cover the full build history across versions and aren't duplicated per-release.
